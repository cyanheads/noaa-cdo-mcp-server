# 0.5.0 — 2026-08-18

## Added

- **`noaa_climate_search_storm_events`**: search the NCEI Storm Events Database for one calendar year — severe-weather events with magnitude, direct/indirect deaths and injuries, property/crop damage, and episode/event narratives — filtered by `state`, `eventType`, `month`, and `minDamageInUsd`. A separate, tokenless corpus from the CDO tools on this server. ([#6](https://github.com/cyanheads/noaa-climate-mcp-server/issues/6))
- **`StormEventsService`** (`src/services/storm-events/`): resolves each year's `_c<publishDate>`-suffixed filename from the live NCEI directory listing rather than constructing it, streams gzip decompression through a hand-written CSV reader so the ~70 MB decompressed file is never held, and caches the listing plus two years of compressed bytes for six hours.
- **`parseDamageEstimate`** (`damage.ts`): three distinct outcomes for a damage cell — not reported, a parsed dollar amount, or an unparseable upstream value — so an unreported figure can never read as a confirmed `$0`. Handles `H`/`K`/`M`/`B` magnitude suffixes and leading-decimal amounts (`.5M`).
- The tool's declared error contract (`year_unavailable`, `service_unavailable`, `malformed_export`) matches every failure the service can produce, including a body that fails to decompress (discarded rather than cached, so a bad download isn't replayed for the rest of the cache TTL) and a stale cached filename (one listing re-resolve before failing).
- Zero-match responses suggest corrections only when the `state`/`eventType` value is genuinely absent from that year's data, and name the filter that actually produced zero.

## Fixed

- `tests/tool-naming.test.ts` omitted `noaa_climate_list_location_categories` from its roster since 0.4.0; both it and the new tool are now covered.
