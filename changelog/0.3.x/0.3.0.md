# 0.3.0 — 2026-08-18

## Changed

- `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.5`
- **Breaking**: date and identifier inputs on all seven tools are now validated Zod schemas instead of unrestricted strings — a malformed date, calendar-invalid date, or blank/whitespace identifier fails locally with `InvalidParams` instead of reaching CDO. ([#20](https://github.com/cyanheads/noaa-climate-mcp-server/issues/20))
- TypeScript `^6.0.3` → `^7.0.2`; `tsconfig.build.json` now typechecks `tests/`; Dockerfile pins `oven/bun:1.3.14`; `bunfig.toml` adds a `minimumReleaseAge` supply-chain guard and the Socket security scanner; `scripts/`, `skills/`, and `.github/` synced from upstream templates.

## Fixed

- **`noaa_climate_fetch_data`**: `includemetadata: false` no longer collapses `totalCount` to the current page size — the upstream CDO request always asks for metadata, and only the tool's own output respects the client's flag. ([#19](https://github.com/cyanheads/noaa-climate-mcp-server/issues/19))
- **Pagination**: an offset past the final page is now distinguished from a genuine no-match. Affected collection tools probe the first page when a nonzero offset returns an empty, metadata-less response, and report the real `totalCount` plus a new `exhausted` enrichment field. ([#21](https://github.com/cyanheads/noaa-climate-mcp-server/issues/21))
- **`noaa://stations/{stationId}`**: declares a typed `not_found` error contract and throws through `ctx.fail`, matching `noaa_climate_get_station`'s existing pattern. ([#23](https://github.com/cyanheads/noaa-climate-mcp-server/issues/23))
- Date validation now accepts every form CDO actually honors — compact `YYYYMMDD`, unpadded month/day in the dashed form, and full ISO-8601 datetimes — instead of rejecting forms the API answers correctly.
- A malformed date or blank identifier now reports one validation message instead of two contradictory ones.
- Collection tools' empty-page text no longer claims "no records matched" when the page is empty because the offset is exhausted, not because nothing matched.
- `CdoService`'s request helper accepts an `expectedStatuses` list for endpoints that treat a non-2xx response as an ordinary outcome — previously unreachable from any caller.
- `noaa://stations/{stationId}`'s `stationId` parameter now runs through the same blank/whitespace validation as the tool surface, closing a gap the tool-wide validation pass skipped.

## Migration

No config changes required. A request that previously reached CDO with a malformed date or a blank/whitespace identifier now fails locally with a Zod `InvalidParams` error instead of an upstream 500, a silently widened query, or a silently dropped filter.
