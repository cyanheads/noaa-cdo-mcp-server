# 0.4.0 — 2026-08-18

## Added

- **`noaa_climate_list_location_categories`**: lists the 12 CDO location categories (`CITY`, `ST`, `CNTY`, `CNTRY`, `ZIP`, `US_TERR`, `CLIM_REG`, `CLIM_DIV`, `HYD_ACC`, `HYD_CAT`, `HYD_REG`, `HYD_SUB`) — pagination and sort only, since CDO ignores every domain filter on this endpoint. ([#22](https://github.com/cyanheads/noaa-climate-mcp-server/issues/22))
- **`noaa_climate_find_locations`**: `nameContains` synthesizes the name search CDO's API lacks — it enumerates the requested category (up to four `limit=1000` fetches) and substring-matches names client-side. Eligibility is a live count read from the category's own first fetch, not a hardcoded list; the bound is 4,000 locations, covering every category but `ZIP` (30,415). Reported `count`/`offset` describe the filtered set when active, via the new `appliedNameFilter` output field. ([#15](https://github.com/cyanheads/noaa-climate-mcp-server/issues/15))

## Changed

- **`noaa_climate_fetch_data`**'s date-range cap now follows the calendar-month boundary CDO actually enforces, rather than a fixed day count — a full leap year (366 days) and a full 10 calendar years (3,652 days) now pass. The `date_range_exceeded` error carries the computed `maxEndDate`. ([#25](https://github.com/cyanheads/noaa-climate-mcp-server/issues/25))
- `NEXRAD2`/`NEXRAD3` now carry the same 1-year cap: CDO enforces it without documenting it, and an uncapped request previously forwarded and returned an opaque upstream 500 in place of the typed error.
- Every date filter is normalized to the canonical `YYYY-MM-DD[THH:MM:SS]` wire form before it reaches CDO (`toCdoWireDate`) — `/data` rejects a compact or unpadded date that every other CDO endpoint accepts, so relaying the caller's raw string made an advertised input form work on some endpoints and not others.

## Fixed

- Dead example identifiers swept from tool/resource descriptions, `README.md`, and `docs/design.md`: `GHCND:USC00450974` (CDO answers it with a bare `{}`) is now `GHCND:USW00024233`; `CITY:US530031` is now `CITY:US530018`; the `CNTRY` category's example ID now carries its actual `FIPS:` prefix. ([#24](https://github.com/cyanheads/noaa-climate-mcp-server/issues/24))
- `noaa_climate_get_station`'s `not_found` throw now uses `ctx.recoveryFor('not_found')` instead of a duplicated, differently-typo'd recovery hint.
