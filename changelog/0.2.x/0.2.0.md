# 0.2.0 — 2026-06-21

Names the workflow (historical climate) rather than one upstream API (CDO). Old npm package deprecated and pointed at the new one. ([#11](https://github.com/cyanheads/noaa-climate-mcp-server/issues/11))

## Changed

- **Package** `@cyanheads/noaa-cdo-mcp-server` → `@cyanheads/noaa-climate-mcp-server`; repo, `bin`, MCP-registry name (`io.github.cyanheads/noaa-climate-mcp-server`), Docker image (`ghcr.io/cyanheads/noaa-climate-mcp-server`), and hosted endpoint (`noaa-climate.caseyjhand.com`) follow.
- **Tool prefix** `noaa_*` → `noaa_climate_*` for all 7 tools: `noaa_climate_list_datasets`, `noaa_climate_list_data_categories`, `noaa_climate_list_data_types`, `noaa_climate_find_locations`, `noaa_climate_find_stations`, `noaa_climate_get_station`, `noaa_climate_fetch_data`. Namespaces climate under the shared `noaa_` root alongside `noaa_marine_*` and `noaa_spaceweather_*`.
- **Tool titles** `NOAA CDO …` → `NOAA Climate …`; resource display names `NOAA CDO Datasets`/`NOAA CDO Station` → `NOAA Climate …`.
- **Server identity** `createApp()` `name`/`title` → `noaa-climate-mcp-server`; `instructions` and recovery hints reference the new tool ids.

## Added

- **`tests/tool-naming.test.ts`** — regression guard pinning the registered set to exactly the seven `noaa_climate_*` ids so a future edit can't reintroduce a bare `noaa_*` name.

## Migration

Update the package name and every tool call:

- npm: install `@cyanheads/noaa-climate-mcp-server`. The old package still resolves but is deprecated.
- Tool calls: prefix `noaa_climate_` (e.g. `noaa_fetch_data` → `noaa_climate_fetch_data`).

Unchanged — no config or client breakage on these surfaces:

- **`NOAA_CDO_TOKEN`** keeps its name (sourced from the NOAA CDO web portal, authenticates against the CDO API).
- **`noaa://datasets`** and **`noaa://stations/{stationId}`** resource URIs are stable.
- Service layer (`src/services/cdo/`, `CdoService`) and upstream-API references to "Climate Data Online (CDO)" stay — CDO is the real API name.
