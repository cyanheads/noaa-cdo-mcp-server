# 0.1.9 — 2026-05-28

## Changed

- **`@cyanheads/mcp-ts-core`** ^0.9.9 → ^0.9.13 — picks up:
  - **`MCP_HTTP_MAX_BODY_BYTES`** — configurable inbound request-body cap (default 1 MiB); oversized requests rejected with `413` before the SDK parses the body ([mcp-ts-core#157](https://github.com/cyanheads/mcp-ts-core/issues/157)).
  - **HTTP session-init gate** — stateful HTTP mode rejects non-`initialize` requests missing `Mcp-Session-Id` with `400`, preventing uninitialized session minting ([mcp-ts-core#154](https://github.com/cyanheads/mcp-ts-core/issues/154)).
  - **`httpErrorHandler`** log-level split — expected client errors (401, 403, 400, 404) now use `logger.warning` instead of full `ErrorHandler.handleError`, reducing stack-trace noise ([mcp-ts-core#158](https://github.com/cyanheads/mcp-ts-core/issues/158)).
  - **`landing.requireAuth` default** — landing page inventory gated behind auth when `MCP_AUTH_MODE` is `jwt`/`oauth`; `requireAuth: false` explicitly set here to keep the public catalog open ([mcp-ts-core#156](https://github.com/cyanheads/mcp-ts-core/issues/156)).
  - **`GET /mcp` `server.keywords`** — consumer `package.json` `keywords` surfaced on the status JSON ([mcp-ts-core#165](https://github.com/cyanheads/mcp-ts-core/issues/165)).
- **`landing.requireAuth: false`** added to `createApp()` call in `src/index.ts` — preserves public-catalog behavior after the framework default change.
- **`@biomejs/biome`** ^2.4.15 → ^2.4.16.
- **Skills synced** — `code-simplifier` added; `api-canvas`, `api-config`, `design-mcp-server`, `git-wrapup`, `polish-docs-meta`, `release-and-publish`, `report-issue-framework` updated; `migrate-mcp-ts-template` removed.

## Security

- **413 body cap** — HTTP endpoint now rejects oversized inbound payloads before parsing, limiting unbounded memory allocation vectors on the MCP endpoint.
