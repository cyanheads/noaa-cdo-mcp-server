# 0.1.12 — 2026-06-04

All six query tools now catch `McpError(InvalidParams)` thrown by the CDO service layer on HTTP 400 responses and re-throw via `ctx.fail('validation_error', ...)` with tool-specific recovery hints. This populates `data.reason` for machine consumers and surfaces actionable guidance. Non-`InvalidParams` errors propagate unchanged.

## Fixed

- **`noaa_fetch_data`** — HTTP 400 from CDO (bad datatype ID, date format, or unknown station/location) now surfaces as `data.reason: 'validation_error'` with a recovery hint referencing `noaa_list_datasets`, `noaa_find_stations`, and `noaa_list_data_types`. The `validation_error` contract entry was declared but unreachable via `ctx.fail` — closing [#8](https://github.com/cyanheads/noaa-cdo-mcp-server/issues/8).
- **`noaa_list_datasets`** — same fix; recovery hint references `noaa_list_data_types` and valid CDO date format. Closes [#8](https://github.com/cyanheads/noaa-cdo-mcp-server/issues/8).
- **`noaa_find_locations`** — added `validation_error` contract entry and catch block; recovery hint references `noaa_list_data_categories` and `noaa_list_datasets`. Closes [#9](https://github.com/cyanheads/noaa-cdo-mcp-server/issues/9).
- **`noaa_find_stations`** — added `validation_error` contract entry and catch block; recovery hint references `noaa_find_locations` and `noaa_list_data_categories`. Closes [#9](https://github.com/cyanheads/noaa-cdo-mcp-server/issues/9).
- **`noaa_list_data_categories`** — added `validation_error` contract entry and catch block; recovery hint references `noaa_list_datasets`. Closes [#9](https://github.com/cyanheads/noaa-cdo-mcp-server/issues/9).
- **`noaa_list_data_types`** — added `validation_error` contract entry and catch block; recovery hint references `noaa_list_data_categories` and `noaa_list_datasets`. Closes [#9](https://github.com/cyanheads/noaa-cdo-mcp-server/issues/9).
