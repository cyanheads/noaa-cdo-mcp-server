# 0.6.0 — 2026-08-18

## Added

- **`noaa_climate_get_billion_dollar_disasters`**: query NCEI's Billion-Dollar Weather and Climate Disasters — individual disasters (name, class, span, CPI-adjusted and unadjusted cost, deaths) or, with `summary=true`, per-year counts and costs by disaster class. Filters by `startYear`/`endYear` (overlap match), `disasterType`, `minCostInUsd`, and `state`. A third corpus on this server: no token, static CSV. ([#12](https://github.com/cyanheads/noaa-climate-mcp-server/issues/12))
- **`BillionDollarDisastersService`** (`src/services/billion-dollar-disasters/`): reads NCEI's four small static exports (national and per-state, per-event and per-year) and converts every cost to whole US dollars. NCEI declares a different unit in each file's own preamble — millions for the per-event file, billions for the national per-year file — so the multiplier is parsed from that preamble rather than hardcoded per file; an unrecognized or absent unit is `malformed_export`. A state-scoped events response carries `costBasis: "national"` since per-state rows hold the whole disaster's national cost, not a state share.
- **`bun run test:live`**: opt-in Vitest project that resolves every example identifier documented in tool descriptions, the README, and `docs/design.md` against the live CDO API, plus every dataset `noaa_climate_fetch_data` gates on. Needs `NOAA_CDO_TOKEN`; the default `bun run test` lane stays hermetic (now scoped to the `unit` project). ([#26](https://github.com/cyanheads/noaa-climate-mcp-server/issues/26))

## Changed

- **`CdoService`** now recovers CDO's own rejection message instead of discarding it. Every 4xx used to reach a tool as a bare `Fetch failed for <url>. Status: 400`, indistinguishable across a bad date form, an over-long range, or a missing parameter, and leaking the fully-parameterized request URL. CDO's `<developerMessage>`/`<userMessage>` (XML faults) or `message` (JSON) is now extracted and surfaced in its place; a failure with no recognizable message gets a hint pointing at long `stationId`/`locationId`/`datatypeId` arrays instead. ([#27](https://github.com/cyanheads/noaa-climate-mcp-server/issues/27))
- **A rejected API token now routes to `upstream_auth_failed`** (`ConfigurationError`), a new reason declared on all eight CDO-backed tools, instead of `validation_error` — whose recovery hint sent the caller to re-verify inputs that were never the problem. The hint names `NOAA_CDO_TOKEN` as the thing to fix. ([#27](https://github.com/cyanheads/noaa-climate-mcp-server/issues/27))
- **`CsvStreamReader`** moved from `src/services/storm-events/csv.ts` to `src/services/csv/csv-stream-reader.ts` now that both Storm Events and Billion-Dollar Disasters parse with it.

## Fixed

- The documented `CLIM_REG:SOUTHATL` location ID example was unresolvable — `CLIM_REG` is a location *category*, not an ID prefix. Replaced with `CLIM:104`, the correct prefix for NOAA climate regions. ([#26](https://github.com/cyanheads/noaa-climate-mcp-server/issues/26))
